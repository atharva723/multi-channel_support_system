Omnichannel AI Support Sentinel: Production Blueprint & Specification
This document details the architecture, data flow, mathematical routing models, and concrete schemas for the Omnichannel AI Support Sentinel. It serves as a comprehensive guide to building a scalable, low-latency, and friction-free customer support automation pipeline utilizing your core stack: n8n + FastAPI + Local/Hosted LLM + PostgreSQL/SQLite + Expo Dashboard.
1. Architectural Philosophy: Bypassing Google's Sandbox
Our prior R&D into the Google Business Profile (GBP) API identified major roadblocks for portfolio showcase developers and early-stage systems:
* Physical Storefront Verification Audits: Google restricts production access to GBP APIs, requiring active business documentation and leaving sandbox developers with a permanent    (Queries Per Minute) quota.
* Complex Oauth 2.0 Consent verification: Accessing user business accounts requires deep security audits and web consent flow approvals.
* Short-lived Access Tokens: Google access tokens expire every 60 minutes, demanding background token refresher jobs and complex database tracking.
The Omnichannel AI Support Sentinel addresses these problems by shifting the integration target from closed search engines to open, high-value workspace APIs (Discord, Slack, and standard IMAP).
Why this Blueprint is Friction-Free:
   1. Instant Discord App Verification: Discord bot tokens are generated instantly with zero developer verification or waiting times.
   2. Personal/Free Slack Workspace Sandboxes: Developer apps can be set up in local test workspaces with complete read/write access.
   3. IMAP Standard App Passwords: By using an app password with standard email protocols (IMAP/SMTP) via n8n, we bypass Google's highly restricted Google Workspace OAuth audits while still processing real-world emails.

6.1. Auth & Configuration Store (src/hooks/useAuthStore.ts)
To keep our user verified without complex storefront logins, we implement a lightweight session manager anchored in Expo's secure enclave storage.
import { create } from 'zustand';
import * as SecureStore from 'expo-secure-store';

interface AuthState {
 authToken: string | null;
 agentName: string | null;
 isAuthenticated: boolean;
 initializeSession: () => Promise<void>;
 authenticateAgent: (token: string, name: string) => Promise<void>;
 deauthenticateAgent: () => Promise<void>;
}

export const useAuthStore = create<AuthState>((set) => ({
 authToken: null,
 agentName: null,
 isAuthenticated: false,
 
 initializeSession: async () => {
   try {
     const token = await SecureStore.getItemAsync('agent_jwt');
     const name = await SecureStore.getItemAsync('agent_name');
     if (token && name) {
       set({ authToken: token, agentName: name, isAuthenticated: true });
     }
   } catch (e) {
     console.warn('Session hydration failed:', e);
   }
 },

 authenticateAgent: async (token, name) => {
   await SecureStore.setItemAsync('agent_jwt', token);
   await SecureStore.setItemAsync('agent_name', name);
   set({ authToken: token, agentName: name, isAuthenticated: true });
 },

 deauthenticateAgent: async () => {
   await SecureStore.deleteItemAsync('agent_jwt');
   await SecureStore.deleteItemAsync('agent_name');
   set({ authToken: null, agentName: null, isAuthenticated: false });
 }
}));

import React, { useRef, useMemo, useCallback } from 'react';
import { View, Text, Pressable, TextInput } from 'react-native';
import { FlashList } from '@shopify/flash-list';
import BottomSheet from '@gorhom/bottom-sheet';

export default function MobileEscalationDesk() {
 const bottomSheetRef = useRef<BottomSheet>(null);
 const snapPoints = useMemo(() => ['40%', '85%'], []);
 const [selectedTicket, setSelectedTicket] = React.useState<Ticket | null>(null);
 const [draftReply, setDraftReply] = React.useState<string>('');

   {

     channel: 'Discord',

 ];

   setDraftReply(ticket.ai_draft_reply);
   bottomSheetRef.current?.snapToIndex(0);
 }, []);

 const handleApprove = useCallback(() => {
   Haptics.notificationAsync(Haptics.NotificationFeedbackType.Success);
   // Execute API mutation here...
   bottomSheetRef.current?.close();
   setSelectedTicket(null);
 }, []);

 return (
   <View className="flex-1 bg-zinc-950 px-4 pt-12">
     {/* Dynamic Header Block */}
     <View className="flex-row items-center justify-between mb-6">

           {mockTickets.length} Escalated
         </Text>
       </View>
     </View>

     {/* Main FlashList Core */}
     <View className="flex-1 w-full">
       <FlashList
         data={mockTickets}
         estimatedItemSize={165}
         renderItem={({ item }) => (
           <Pressable 
             onPress={() => handleTicketSelect(item)}
             className="bg-zinc-900 border border-zinc-800 rounded-2xl p-5 mb-4 active:opacity-90"
           >
             <View className="flex-row justify-between items-center mb-2">

               "{item.content}"
             </Text>

             <View className="bg-zinc-950 border border-zinc-800/80 p-3 rounded-xl">
               <Text className="text-[10px] font-bold text-indigo-400 uppercase tracking-widest mb-1">Draft Response</Text>

     >
       {selectedTicket && (
         <View className="p-6 flex-1 justify-between">

             {/* Draft Box */}
             <View className="bg-zinc-900 border border-zinc-800 rounded-2xl p-4 min-h-[140px]">
               <TextInput
                 multiline

7. Direct Resolution of GMB Research Bottlenecks
Identified Problem (Google Maps GMB Integration)
	Strategic Solution (Omnichannel Support Sentinel)
	Physical Location Verification Audit Requirements
	Bypassed. Discord and Slack require zero location validations. Email integrations utilize simple IMAP App Passwords.
	Hourly background refresh token expires
	Eliminated. Both Discord bots and Slack app tokens utilize permanent API keys that never expire, cutting out token table sync engines.
	Sandbox restrictions during development
	Friction-Free. Developers can create clean, local target test servers/workspaces for Discord/Slack in 2 minutes, allowing complete, live end-to-end sandbox execution.
	Google Client Secret leaks on mobile runtime
	Separated. Frontend application clients never see platform client secrets. All data validation and system handshakes happen on your FastAPI routing proxy, protecting your private server keys.
